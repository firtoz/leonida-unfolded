# Performance and fidelity TODO

Each numbered item is a standalone assignment. Pick one item per agent and ask for an accept, revise, or park decision with evidence. The sample island is the starting point for synthetic checks. The recorded demo routes and authorized local game files are needed for real-scene qualification.

## How to run a follow-up

1. Give the agent one item, a clean worktree, the baseline revision, and the private route and fixture locations it needs. Capture the exact baseline and candidate revisions before requesting hardware.
2. Share one queue directory and dispatcher per machine. Use the standalone [Resource Queue CLI and portable agent skill](https://github.com/firtoz/resource-queue) with a pool of one slot for the shared CPU and GPU benchmark machine. Put the entire timed job, including browser startup and shutdown, under that reservation. Agents can develop in their worktrees while their jobs wait. On other projects, pool capacity can reflect independent resources, such as two device simulators. If the simulators have distinct device IDs, use a named single-slot pool for each device. Jobs that share a bottleneck should also reserve the corresponding shared pool.
3. Match the browser, viewport, quality settings, preload state, and camera path. Run the same build twice to establish timing variation if a result is close. Alternate baseline and candidate order, run fresh and reopened folder sessions where loading is relevant, and report each pair. Use a fixed render buffer to isolate GPU effects and an ordinary adaptive run to check user impact.
4. For loading, record folder selection to usable map, Explore to usable foreground, and time to settled coverage as applicable. For motion, record frame pacing and long frames alongside FPS. Check the matching settled views for missing or duplicate geometry, material changes, and altered view distance. Record which result the measurements support and what would change the decision.
5. Follow the [contribution guidelines](CONTRIBUTING.md). Keep private routes, captures, raw logs, and game files local. Report sanitized aggregate results and test conditions. For code changes, run the checks in the contribution guidelines.

For an agent handoff, copy and fill in this prompt.

> Investigate TODO item **[number and title]** in your own worktree. Compare against **[baseline revision]**. Use **[private route or synthetic fixture]** and put timed runs through **[queue directory and pool]**. Keep evidence local. Report the job IDs, revisions, repeated loading and frame-pacing results, what changed visually, and whether to accept, revise, or park the candidate.
